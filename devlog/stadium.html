4. 苦労したこと・直したこと（テーマ別）

4-1. 3Dを「ファイルを開くだけ」で動かす

Three.js3Dのライブラリは ふつう「部品を読みこむ」形（import）で、ファイルを開くだけ（file://）では そのまま使えない。この作業環境では いつもの入れ方（npm）も ブロックされた → GitHub から Three.js の本体を取ってきて、script タグ1つで読める形に 自分で変換 絵を3Dにfile:// では 画像ファイルを 3D（WebGL）に わたせない → モンスターの絵は 文字のデータ（data URL）にして わたす 絵が出ない1ファイル版にしたら、入場シーンで モンスターが出ないことがあった。原因：絵の読みこみが 3Dの最初の表示より おそいと、あとから絵の大きさを変えていたため、3D側が 受けつけなくなっていた（WebGL は あとから大きさを変えられない）→ 絵の台紙を 768×768 に固定

4-2. キャラが 暗い・ぼやける

解像度
（0.2.0）「気のせいかな？」→ 気のせいではなかった。3Dを 1280×720 で描いて、電子黒板の大きさに 引きのばしていた → 映る大きさに合わせて 最大2倍の こまかさで描く。0.3.0 では ドット絵を4倍にしてから 縮小して くっきりに 暗い
（0.3.2）入場・表彰で キャラが暗く ぼやける。原因：まなびバトルの「対戦画面の背景を ぼかして暗くする」設定が、後ろの3D全体に かかっていた → スタジアムでは その設定を消し、入場・勝利は 背景を すかす

4-3. 観客と カメラ

カメラ入場の はじめに スタジアムを回りこむカメラが、観客席の外がわ（壁の裏）を通っていた → 観客席の上・内がわを 高い位置から回る 観客の重さはじめの観客は 箱 約2700個を、1つずつ毎回 計算して はねさせていた → モンスターの観客に するとき、全員を まとめて1回で描き、はねる計算は グラフィック側（GPU）に。絵は増えたが 計算は へった チカチカ
（0.4.0）観客のうち 緑の子（理科の2体）だけ チカチカする。観客10体は 1枚の絵に まとめて切り出している。キャラの番号の計算に ごくわずかな ずれが出て、となりの絵との 境目を またいでいた → 番号を きっちり丸める・絵と絵の間に すき間を あける。こちらの環境では チカチカを再現できず、直ったかは 実機で確認してもらう形だった

4-4. 重さ（電子黒板・先生のPC）

かるい
モード公開版が 1ファイル版より重い → タイトルに スイッチ（PCに おぼえる）。画面の こまかさ 約6割・観客 約3分の1・サーチライトの光のすじ なし・エフェクト半分。暗号化版は 開くときに もとにもどすので、読みこみの数秒は 重くなる 引っかかり
（0.4.2）1ファイル版だけ、UIの表示・ルーレットで 引っかかる（2作とも）。原因：画像を 長い文字のかたまり（1枚 数十〜数百KB）のまま 画面に入れていて、画面を切りかえるたびに 読みなおしていた → 開いたときに 短い名前（blob:）で呼べる形に かえ、画像も 先に読みこむ。先生のPCは ハードウェアアクセラレーションが オフ（先生の話）で、3Dや ぼかしを CPU だけで計算していたことも 重さの一因

4-5. 素材の権利と 公開

  • 先生の疑問「HTMLに固めて公開しても再配布？」「フリーゲームは たくさんあるのに、違いは？」から、使っている素材（絵・BGM・効果音・UI・フォント）の規約を 1つずつ調べて 一覧に
  • 違いは「技術的に取り出せるか」ではなく「ゲームとして遊ばせているか、素材ファイルとして配っているか」。素材のファイルを そのまま 公開リポジトリに置くのは NG
  • Claude は はじめ 効果音ラボを「⚠️〜❌」にしたが、よくある質問に「音源ファイルむき出しでも問題ない（できれば隠して）」「GitHub公開も再配布とみなさない」とあり、まちがいだったので 訂正した
  • 結論：素材は非公開のまま、公開側には 暗号化した1ファイル版だけを置く（ツクールの暗号化と同じくらいの「隠す措置」。カギは中にあるので 完全ではない）。規約が はっきりしない 3つ（BGMの1つ・モンスター素材・アイコン素材）は 作者に たずねると安心、と伝えた
  • 暗号化していない版を 一度 公開リポジトリに上げて消した 記録が残っていた → リポジトリごと 作りなおしてもらい、暗号化版だけを置きなおした

4-6. 子どもが前に出て遊ぶための 配慮

  • アイテム選びは「ふせて選ぶ」：選ぶ人以外は 後ろを向く。選んだアイテムは 入場で「？」から 1つずつ 発表
  • 問題の 正誤は 大画面に出さない（攻撃力だけ発表）。まちがえたときの 解説は 1秒で 自動で消える（スタジアムだけ）
  • 電子黒板の上のほうは 子どもの手が届かない → 決定ボタンを 右下に
  • 先攻を取られて 負けが決まった場面のために「パス（こうさん）」。押すと 確認が出る
  • UIの位置・ルールは まなびバトルと同じ（子どもが とまどわないように）

5. 先生の口ぐせ・こだわり（このチャットで見えたこと）

  • 見た目は はっきり言う：「ちゃっちい」「ださい」「キャラが暗い」。いったん入れた花吹雪も 見てから「やっぱりいらない」
  • 番号つきで 一度に いくつも頼む（「１ … ２ …」）。直したら すぐ「ZIPください」「zip」「htmlにまとめて」で 実機で試す
  • 使う場面から考える：電子黒板・子どもの手の届く高さ・後ろを向く・正誤を見せない
  • 「まなびバトルのプレイヤーが戸惑わないように」：ルールも UI の位置も 変えない
  • 重さは自分のPCで確かめる（職場のPCで 60FPS、家では ハードウェアアクセラレーション オフで 重い）
  • 公開の前に 素材の権利を 気にする
  • サンプルを見て「すごくない？感動しちゃった」
