1. どんなゲームか（30秒で）

  • 小4〜6向け。5教科 2500問（各500問）に答えて モンスターを育て、ボスと戦う。友だちと QRコードで1台対戦
  • はじめは「たんさいぼう」→ 最初のダンジョンで 第1段階 → 第2 → 第3（最終進化）。毎日ふつうに遊ぶと 7日目ごろ・21日目ごろに進化（シミュレーションで決めた）
  • ごはん（キャンディ／肉）で せいかくが変わり、かわいい系／かっこいい系に。タイプ6×系統2×3段階＝36体＋たんさいぼう。キャラ・ボス・雑魚はぜんぶ のち先生の手描き
  • まちがえた問題は「復習まち」→ 復習ダンジョンで 2回正解して卒業（4択のまぐれ正解をなくすため）
  • アイテム100個（★1〜★5）、ガチャ、ログインボーナス、無限の塔（1日10分）、とうぎじょう、アチーブメント、用語集
  • 2026/10/14 にクラスで初配布。学校の端末は Canva のサイトしか開けないので、本番は Canva サイト版（1ファイル・10MB以内）

2. 体制と やりとりの「型」

のち先生企画・ゲームデザイン・キャラの絵・判断・実機テスト（子どもが遊んで 気づいたことを スクショつきで 短く指示）。プログラミングは ほぼ未経験。

Claude仕様書づくり・実装（HTML/CSS/JavaScript）・自動テスト・ビルド・公開。素の HTML/JS で、ファイルを開くだけで動く作り（サーバーなし）。

よく出てきた「型」

  • スクショ＋ひとこと：「ボタンがかぶっているのは悪いUI」「Pの文字が見えなくなるから反転させないで」のように、画面を見せて短く指示 → Claude が原因を調べて直す
  • 「まだ実装しないで」：大きな変更は まず案・仕様・一覧を出して、先生が決めてから作る（アイテム刷新・QR形式・用語集など）
  • 「全バージョンに実装」＝ 毎回この5つ：GitHubに保存 → 公開版を更新 → Canva版（10MB以下を確認）→ 1ファイル版 → Teams用ZIP。ファイルで先生に渡す
  • 途中で追加：作業中に「さらに追加で…」と 次々に要望が来る（2.0.0 の作業中に7件など）。まとめて 同じ版に入れる
  • 引き継ぎメモ（HANDOFF.md）：長いチャットは途中で新しくするので、仕様・決めたこと・先生の好み・つまずきを ぜんぶメモに残し、次のチャットが最初に読む。メモは 約6万字に育った
  • 自動テスト：Playwright（ブラウザを自動で動かす）で 自動プレイBOT・各モードのテスト 約20本・全123画面の見た目点検（ui_audit）。直したら毎回まわす

4. 苦労したこと・直したこと（テーマ別）

4-1. 学校のフィルターと Canva サイト

学校の端末は GitHub などが開けず、Canva のサイトだけ開ける。だから「1つのHTMLを Canva に置く」作りにした。Canva は 10MB まで。

容量画像・音・フォントを全部埋めこむと 17MB → BGMを 16kbps モノラル、フォントは使う字だけ、背景・手描き絵は WebP に圧縮。最終進化の絵などが増えるたびに 10.19MB → 9.92MB のように ギリギリの戦い（使わない絵を消す・魔法陣も圧縮） 画面が切れるCanva は ゲームを枠（iframe）に入れて表示 → 下がはみ出す → 実際に見えている範囲を測って そこに合わせる（まなびドラゴンで先に経験） 背景が出ないCanva 上だけ タイトルの背景が出ない → 背景を画像として一番うしろに置く セーブが消える同じURLでも HTML を差しかえると 子どものセーブが消える → 根本対応は せず、タイトルのバージョンを10回タップ → QRで復元（先生だけが知っている） Canva版だけ
ボスが逆配布当日の朝に先生が発見。ファイルを開く版は正しいのに Canva版・1ファイル版だけ ボス15体が左右反転。原因：画像を埋めこむと 画像の場所（ファイル名）で「手描きのボスだから反転しない」と見分けられなくなっていた → 場所で判断するのをやめて直した（2.0.3）。数時間後のリリースに間に合わせた

4-2. UIの「ずれ」との戦い

先生は アイコン・ボタン・文字・ゲージの 高さや大きさが そろっていないと 気持ち悪いタイプ。ここが いちばん やりとりが多い。

1.4.2自分と敵のゲージの高さがずれる（称号がない子だと行がつまる）→ 称号の行は 称号なしでも場所をとる。スキルボタンの上下の段で大きさをそろえる、パネルの幅をそろえる 改行最後の行に1〜2文字だけ残る「へんな改行」を 全123画面から自動で探すツール（ui_audit）を作り、0件にしてから出す。用語に下線を付けたら また改行がくずれた → 用語ととなりの1文字を くっつけて折り返さないようにした スクロール「ボタンがかぶっているのは悪いUI」：せいちょう画面の とじるボタンが スクロールバーに重なっていた → 見出しを固定して 中だけスクロール ぴくぴく「バトルスタートボタンにマウスを合わせると奇妙な動きをする」→ ボタンを中央に置くやり方と、マウスを乗せたときの ぴょこっと動く演出が ぶつかって、右にずれる→マウスが外れる→戻る を くり返していた はみ出しもちもののリスト表示で アイコンの絵が枠からはみ出す・見出しとアイテム名の文字の大きさが同じで見づらい → 枠ごと縮小・名前は1色・見出しは「■」つきで大きく

4-3. 絵（手描きを ゲームに入れる）

  • 主人公は 何度も入れかわった：フリー素材（仮）→ 先生のピクセルアート → 手描き → 手描きをドット化 → なめらかな手描き（いま）
  • 元の絵の 目の光まで透明になっていた2体 → 穴を自動で白く埋める。体から離れた小さな点（ごみ）を自動で消す（10枚が直った）
  • 雑魚22体は 1枚の紙に描いた絵から切り出し、手書きの名前を消し、線をなぞりなおして大きく
  • 左右の向き：戦闘では 右側の敵を反転して左向きにする。でも 文字が入った絵は反転すると読めない → ボス（もとから左向き）と「Pマン」（Pの文字）は反転しない
  • キャラのまわりの ふちの色は「キャラに合わせた色にしてほしい」→ 絵の いちばん目立つ色を 自動で計算
  • 最終進化は ネタバレ禁止（ガイドブックやSNSでは 第1段階だけ・進化先はシルエット）

4-4. バランス（シミュレーションで決める）

  • ボスの強さ：本物の計算のまま 何千回も自動で戦わせて、「アイテムあり全問正解でだいたい9割勝てる・アイテムなし正答80%で半分くらい」に合わせた
  • 進化の時期：自動プレイBOT（毎日ダンジョン2回＋復習・正答率80%）で 1日に上がる量を はかって 7日目・21日目に
  • アイテム100個：1個ずつ・強い組み合わせ（コンボ）とも くらべて、勝率40〜60%に 100個中80個が入るように調整
  • ガチャ：★5は2%・10回目は★4以上。「重複で出るかもなのに？」→ コンプまでの日数をシミュレーション（毎日15回で 半分の子が約25日）。先生は「ガチャ1回のコイン数はかえたくない」→ 確率のほうを調整
  • 対戦：3問×5ターンにしたら 時間切れ判定が増えた → HPを1.4倍に

4-5. 学びの設計

  • 2回正解で卒業：4択は たまたま当たる。1回目の正解は「あと1回」、別の日の復習ダンジョンでもう一度正解して卒業
  • 先生の「おんなじ問題ばっか」→ 出題を作りなおし：①復習まち（同じ教科の問題を3問はさんでから）→ ②新しい問題 → ③おさらい
  • 復習ダンジョンはスタミナ不要で、新しい問題と同じだけ強くなれる（ステータス+8・コイン+40）。まちがえた問題こそ得をする
  • 2517問 → 「500×5でぴったり2500問にすると不都合ありますか？」→ 17問けずって ちょうど2500問に（セーブは番号の対応表で自動引きつぎ）
  • 用語集：説明文の用語に下線 → タップで意味。「60語は多い…まとめて」で 30語に。おぼえていないスキルは ？？？

4-6. 子どもへの配慮

  • 先生の方針：「かしこい子が有利になりすぎない」「負けた子・休んだ子が萎えない」「人間関係に問題が出ない」
  • 友だちのQRを読むときも 正解率は見せない。名前を決めるときに「みんながいやな気もちにならない名前に」
  • 遊びすぎない：スタミナ（1日 ダンジョン2回ぶん）・無限の塔は1日10分。スタミナは2000までためられる（1日休んでも差がつかない）
  • データの引きつぎは 先生だけ（デバッグモードの入口は ひみつ・引きついだら必ずオフ）

4-7. QRコード（セーブを持ち運ぶ）

サーバーがないので、セーブを QR にして 対戦・引きつぎに使う。配布前日に「明日初配布するため、QRの仕様を最終決定」。

  • 2500問の状態・ステータス・アイテムなどを 1枚のQRに → 外部ライブラリが使えない環境だったので 圧縮のしくみを自作（レンジコーダー）。300パターンで壊れないか確認。QRは だいたい120〜850バイト
  • 形式3で確定。これからは「うしろに足すだけ」で 子どものデータを壊さない
  • QR画面は スクショで共有するので「上に名前・左にモンスターとステータス・右にQR・下に日時」
